# Brique visual language

One illustration, one distinction. Contexts are blue enclosures; Capacities are green rectangles; Matters are yellow circles; Documents are folded blue pages. Schemas use a labeled dashed outline. Structures use labeled reference arrangements. Orange execution flow is introduced only in movement D; earlier compositions use dashed green relations. Blue dashed relations indicate observation or a labeled return, not invocation. Use geometry and labels as well as color. Preserve positions across successive frames when possible. Each illustration has a light and dark variant with identical geometry. A picture element selects the variant. The explicit background preserves contrast independently of the surrounding page.


### Movement E

Blue dashed arrows indicate movements of understanding, not execution. Preserve the same geometry when changing perspective; use emphasis to distinguish readings, never to imply a change of identity. Distinguish Context containment from conceptual section nesting with labels and color.

### Movement F

Use labeled forms for distinct crystallizations; a dashed open resolution remains inside a situated world. Blue dashed arrows express possible movements of understanding, not a workflow. Orange indicates an authorized edit when mobilized, not a conceptual relationship.

### Movement G

Actors use neutral labeled capsules. Preserve the Music world across representations; blue dashed arrows express perception, orange directed arrows express execution Intentions. A representation is not a new architectural element.

### Movement J

Separate structured decisions, validation, execution effects and incoming work. Use orange for actual invocation and blue dashed links for perception or correlation. A waiting interval must not contain a running inference. Distinguish mailbox references from full journal messages.

### Movements K–M

Keep independent Continuities visually separate. Show an experience as a yellow Document, not a new architectural type; identify proposed memory behavior explicitly. Use dotted associations without arrows for non-execution relationships. Distinguish a proposed requirement from validated architectural enrichment.

### Part III

Use diagrams for architectural distinctions and literal commands for operations. Do not simulate screenshots as evidence of actual UI behavior. Distinguish source-checked procedures from live validation.

### Part IV

Use diagrams for distinctions; keep exact contracts and operational examples in text. Distinguish design from implemented mechanisms and source checks from live validation.

### Part V

Use comparative compositions for hypotheses and label them as such. Never present hypothetical improvements as measured outcomes. The closing diagram returns to the initial world and distinguishes open possibilities from active execution.

## Theme palette

The [palette](palette.json) defines the four light families; [dark mapping](dark-palette.json) maps each original color to its dark counterpart. Dark surfaces recede and text and strokes become lighter. Geometry, labels and relationship patterns remain invariant. Use a single architectural distinction per diagram; do not treat these illustrations as runtime traces.
